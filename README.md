# Складской учёт — версия 2 (полный перенос макета)

Это обновлённая серверная версия, которая содержит **всю** функциональность из последнего макета: логин/QR-вход, варианты упаковки, штрихкоды, секундомер, объявления, графики, экспорт в Excel/PDF, тему, звук, журнал входов и т.д.

## Что внутри и как это устроено

- `server.js` — сервер на Node.js (Express). Отдаёт готовую страницу и простое key-value хранилище (аналог того, что использовал макет внутри Claude).
- `public/bundle.js` — **уже собранное** приложение (React + графики + Excel), собирать на сервере ничего не нужно.
- `public/index.html` — страница-обёртка, подключает `bundle.js`.
- `src/App.jsx`, `src/entry.jsx` — исходный код (на случай, если понадобится что-то поправить и пересобрать заново, см. ниже).

### Где хранятся данные

- Общие данные (сотрудники, записи, цены и т.д.) — на сервере, в файле `data/store.json` (в общем API `/api/kv/...`).
- Личные настройки одного устройства (тема, звук, язык) — в `localStorage` браузера, прямо на устройстве пользователя. Это нормально для отдельного сайта (в отличие от версии внутри Claude, где это было запрещено).

## База данных (PostgreSQL) — как подключить

Сервер теперь умеет работать с PostgreSQL. Если задать переменную окружения `DATABASE_URL` (или набор `PGHOST`/`PGPORT`/`PGUSER`/`PGPASSWORD`/`PGDATABASE`) — данные хранятся в базе и **не стираются** при обновлении/пересборке приложения. Если переменные не заданы — сервер по-старому пишет во временную папку (`os.tmpdir()`), и данные стираются при каждом деплое.

**Одну базу данных можно использовать для нескольких разных проектов одновременно** — сервер добавляет к каждой записи имя проекта (`PROJECT_NAME`, по умолчанию `packer-tracker`) и хранит всё в одной таблице `kv_store` с колонками `project` + `key`. Проекты с разными `PROJECT_NAME` физически не могут перезаписать данные друг друга, даже если у них случайно совпадут названия ключей.

### Как создать базу на Timeweb

1. В панели Timeweb Cloud откройте раздел **Базы данных** → «Создать базу данных» → выберите **PostgreSQL**.
2. Выберите минимальный тариф (обычно ~200-300 ₽/мес хватает для такой задачи), тот же регион, что и приложение (Москва).
3. После создания откройте базу — там будут параметры подключения: хост, порт, имя пользователя, пароль, имя базы данных.

### Как подключить к приложению

1. В настройках приложения на Timeweb App Platform (раздел «Переменные окружения» / Environment variables) добавьте:
   - `DATABASE_URL` — строка вида `postgres://пользователь:пароль@хост:5432/имя_базы` (Timeweb обычно показывает готовую строку в карточке базы — можно скопировать её целиком).
   - `PROJECT_NAME` — `packer-tracker` (можно не задавать — это значение по умолчанию).
2. Сохраните переменные, зайдите в «Настройки» стенда → «Коммит» и выберите последний коммит (см. раздел 21 истории проекта — иначе задеплоится старый код).
3. Передеплойте приложение.
4. В логах при старте должно появиться `✅ Подключено к PostgreSQL, проект: "packer-tracker"`. Если вместо этого видите `⚠️ PostgreSQL не настроен` — значит переменные окружения не подхватились, проверьте название `DATABASE_URL`.

### Чтобы добавить в эту же базу ещё один проект в будущем

Разверните новый проект (свой отдельный `server.js`/приложение) и укажите ему **тот же** `DATABASE_URL`, но **другой** `PROJECT_NAME` (например `project-2`). Таблица `kv_store` создастся автоматически при первом запуске, если её ещё нет — ничего вручную настраивать не нужно.

### Резервные бэкапы — по-прежнему полезны

Кнопка **«Скачать бэкап (JSON)»** внутри приложения (Настройки → Резервная копия) остаётся полезной как дополнительная страховка (человеческая ошибка, случайное удаление и т.п.), но теперь уже не единственная защита — если база подключена, обновления кода данные не затрагивают.

## Как развернуть на Timeweb (App Platform)

1. Загрузите содержимое этой папки в тот же (или новый) репозиторий на GitHub — так же, как в прошлый раз (через «Upload files», предварительно распаковав архив).
   - **Не нужно** загружать папку `node_modules` — её там нет, но если вдруг появится, не грузите.
2. В Timeweb App Platform, в настройках приложения:
   - Тип: **Backend → Node.js → Express**
   - Команда запуска: `npm start`
   - Остальное — как настраивали в прошлый раз.
3. Разверните (или перезапустите деплой, если обновляете существующее приложение).

## Если понадобится что-то поменять в коде дальше

Если Claude (или вы сами) поменяет `src/App.jsx`, файл `public/bundle.js` нужно пересобрать заново. Проще всего — попросить Claude сделать это и прислать обновлённый архив, пересборка происходит автоматически перед выдачей файла.
