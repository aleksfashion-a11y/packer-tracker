# Складской учёт — версия 3

Приложение для упаковщиков: учёт упаковки и часов, расчёт зарплаты, чат, остатки упаковочных материалов, синхронизация каталога с Ozon.

## Как устроено

- `server.js` — сервер (Node.js + Express): вход и сессии, права доступа, хранилище данных, синхронизация с Ozon, ежедневные снимки.
- `lib/` — части сервера:
  - `build.js` — сборка интерфейса (см. ниже);
  - `auth.js` — пароли, сессии, защита от перебора;
  - `access.js` — кто что может читать и менять;
  - `patch.js` — применение изменений к данным (слияние одновременных правок).
- `src/` — исходники интерфейса:
  - `App.jsx` — всё приложение;
  - `entry.jsx` — точка входа;
  - `storage.js`, `kvdiff.js` — обмен данными с сервером (отправляются только изменения).
- `public/` — страница-обёртка, service worker, иконки.

## bundle.js собирать не нужно

Сервер **сам** собирает интерфейс из папки `src/` при каждом запуске (занимает пару секунд). На GitHub загружаются только исходники. В логах приложения при старте должна быть строка:

```
✅ Интерфейс собран за ... мс (сборка ...)
```

Если вместо неё `❌ Не удалось собрать интерфейс: ...` — в сообщении будет причина (чаще всего не установились пакеты при деплое). Сайт в этом случае показывает сообщение об ошибке; чтобы вернуть рабочую версию — выберите в настройках стенда предыдущий коммит и передеплойте.

Старый файл `public/bundle.js`, если он остался в репозитории, больше не используется — его можно удалить.

## Обновление приложения

1. Распаковать архив, перетащить его содержимое на страницу «Upload files» репозитория на GitHub (с главной страницы репозитория, папки — мышью).
2. В Timeweb: «Настройки» стенда → «Коммит» → выбрать самый свежий коммит → деплой.
3. В логах проверить две строки: `✅ Подключено к PostgreSQL` и `✅ Интерфейс собран`.

## Вход и безопасность

- Логин и пароль проверяет сервер. После входа в браузере хранится только ключ сессии (cookie, недоступная скриптам); сессия живёт 180 дней с последнего захода и переживает обновления приложения.
- Пароли и секретные слова хранятся в виде хеша с солью (scrypt). Учётные записи, созданные в старых версиях (SHA-256), продолжают работать и переводятся в новый формат при первом входе.
- Без входа сервер не отдаёт никакие данные. Сотрудник получает только свои записи, свои замеры, общий чат и свой личный чат; справочники (каталог, цены, остатки упаковки) — только на чтение, кроме остатков и привязок упаковки.
- Цена за штуку и почасовая ставка в записи сотрудника берутся из данных сервера, а не из запроса браузера.
- Ключи с префиксом `_` (ключи Ozon, сессии) через общий API недоступны никому.
- Ключи Ozon и QR-коды входа шифруются в базе (AES-256-GCM), если задана переменная окружения `APP_SECRET` (случайная строка от 16 символов). Ключ шифрования в базе не хранится. Если `APP_SECRET` потерять или изменить — ключи Ozon нужно будет ввести заново, а прежние QR-коды перестанут действовать (пароли это не затрагивает).
- Самостоятельную регистрацию можно закрыть: Настройки → Данные и безопасность.

## База данных (PostgreSQL)

Если задана переменная окружения `DATABASE_URL` (или `PGHOST`/`PGPORT`/`PGUSER`/`PGPASSWORD`/`PGDATABASE`) — данные хранятся в PostgreSQL, в таблице `kv_store` (`project` + `key` + `value`). Если нет — во временной папке, и стираются при каждом деплое.

Одну базу можно использовать для нескольких проектов: каждому задаётся свой `PROJECT_NAME` (по умолчанию `packer-tracker`).

## Резервные копии

- Сервер сам раз в сутки делает снимок данных и хранит последние 14 (Настройки → Данные и безопасность → список снимков).
- «Скачать бэкап (JSON)» — полная копия: сотрудники (с хешами паролей), записи, цены, каталог, фото, упаковка, объявления, чат, настройки.
